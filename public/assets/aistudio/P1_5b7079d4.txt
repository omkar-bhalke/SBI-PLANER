PROJECT: PERSONAL EXPENSE MANAGEMENT & AI FINANCIAL ASSISTANT

ROLE AND RESPONSIBILITY

Act as a senior Android application developer, UI/UX designer, backend engineer, database architect, and AI integration specialist.

Your task is to design and develop a complete, professional, production-ready Native Android application for personal expense management, financial tracking, spending analysis, and financial discipline.

This must be a REAL application with functional features, proper database connectivity, authentication, and a scalable backend architecture.

Do not create just a frontend prototype, static dashboard, HTML website, or WebView application.

Follow the requirements below carefully.

---

1. APPLICATION DEVELOPMENT TECHNOLOGY

Build the application using the following architecture.

Android Application

- Native Android development.
- Kotlin programming language.
- Jetpack Compose for the user interface.
- Material Design 3.
- MVVM architecture.
- Navigation Component.
- Kotlin Coroutines and Flow.
- Room database for local caching and offline support.
- Retrofit or Ktor for backend API communication.
- Android DataStore for application preferences.

Backend

- Node.js with Express.js.
- REST API architecture.
- Backend deployment on Railway.
- MySQL database hosted on cPanel.
- Secure communication using HTTPS.
- Background processing designed for future integrations.

Database

- MySQL.
- Separate user records.
- User-specific transactions.
- User-specific financial settings.
- User-specific spending limits.
- User-specific AI configurations where applicable.

Important Architecture Rule

Keep Android, backend, and database as separate modules.

Do not hardcode server URLs, API keys, database credentials, or authentication secrets throughout the application.

Use environment variables and configuration files.

The architecture must allow additional functionality to be integrated without rebuilding the entire application.

11. EMERGENCY SPENDING APPROVAL – FUTURE MODULE

Design a separate emergency approval module.

Example:

A student has reached the daily spending limit but urgently needs to print an assignment.

The AI should:

1. Analyze the uploaded screenshot.
2. Extract relevant context.
3. Understand the claimed emergency.
4. Evaluate whether the expense appears necessary.
5. Return an explanation and recommendation.
6. Request explicit user confirmation before applying an exception.

If approved, the backend can issue a temporary spending allowance.

Important Safety Requirements

- Never automatically approve payments based solely on a screenshot.
- Allow the user to review and confirm the decision.
- Keep an approval history.
- Define a maximum emergency allowance.
- Apply an expiry time to temporary approvals.

For the initial version, create the UI and backend interface structure only.

Actual AI screenshot verification and payment exceptions will be implemented later.

3. Verify successful synchronization.

5. Update the dashboard.
6. Handle synchronization failures safely.
